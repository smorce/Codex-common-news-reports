## 「Irodori-TTS v4」を試す

### Executive Summary
- Irodori-TTS v4 Small は、従来分かれていた base 系と Voice Design 系を単一チェックポイントに統合した TTS モデルとして紹介されている。
- テキストエンコーダが ModernBERT-ja ベースに置き換わり、日本語発話精度の向上が期待されている。
- 推論は CLI、Gradio Web UI、Hugging Face チェックポイント形式に対応し、uv sync のバックエンド指定も整理されている。
- 音声クローン、参照音声なし生成、キャプションによる音声デザインを試し、生成速度や効き具合が観察されている。
- 音声デザインはリファレンス音声と組み合わせられるが、プロンプト効果は参照音声のトーンに影響される可能性が示されている。
- 長い参照音声は最大 120 秒まで扱えるが、実用上は同一話者の短いクリップを合計約 30 秒用意する方針が推奨されている。
- Speaker Inversion は参照 latent の単純なキャッシュではなく、話者特徴を軽量に学習する仕組みとして整理されている。
- Web UI は通常生成と音声デザインで別スクリプトが用意され、VRAM 5〜6GB 程度で動きそうだと報告されている。
- 筆者は MIT ライセンスでモデルやコードが公開され、ファインチューニング、LoRA、Speaker Inversion まで選べる点を高く評価している。

## 「Qwen-Audio-3.0-ASR-Flash」を試す

### Executive Summary
- Qwen-Audio-3.0-ASR-Flash は、文脈理解、専門用語認識、ホットワード、構造化テキスト化を改良点として紹介されている。
- 内部テストでは医療用語 95.36%、工業用語 93.24% の認識率が示され、専門分野での精度が強調されている。
- モデルはリアルタイム WebSocket、オフライン HTTP の filetrans、短時間向け flash の 3 系統として整理されている。
- ホットワードには事前コンパイル済みとインスタント指定があり、プロンプトコンテキストも認識精度向上に使える。
- 日本語を含む多言語対応が説明され、中国語では方言にも対応するとされている。
- 筆者は Alibaba Cloud の API キーとワークスペース ID を使い、5 分程度の日本語音声を HTTP API で試している。
- 非リアルタイム同期 API では 15〜20 秒程度で応答が返り、単語レベルのタイムスタンプを含む冗長なレスポンスが確認されている。
- ファイルサイズ上限は文書間で 2GB と 10MB の記載揺れがあり、筆者は後者の可能性が高いと見ている。
- 話者ダイアライゼーションの対応有無はモデル種別で異なり、qwen-audio-3.0-asr-flash は非対応と整理されている。

### Key Findings
- 新モデルの主な改良は文脈一貫性、専門用語、ホットワード、構造化テキスト化である。 [^]
  - Footnote: 冒頭に「文脈の一貫性向上」「専門分野用語の認識精度向上」「カスタムホットワード機能追加」と列挙されている。
- 内部テストでは医療用語と工業用語で高い認識率が示されている。 [^]
  - Footnote: 記事に「医療用語の認識率：95.36%」「工業用語の認識率：93.24%」とある。
- モデルバリエーションは streaming、filetrans、flash の 3 種類で、API と機能が異なる。 [^]
  - Footnote: 表に qwen-audio-3.0-asr-flash-streaming、filetrans、flash の用途、API、機能、音声最大長が整理されている。
- filetrans は話者ダイアライゼーションに対応する一方、streaming と flash は非対応とされている。 [^]
  - Footnote: モデル表の話者ダイアライぜーション欄で filetrans は◯、streaming と flash は☓となっている。
- flash のファイルサイズ上限は資料に 2GB と 10MB の記載があり、筆者は 10MB の可能性を指摘している。 [^]
  - Footnote: 記事に「値がぶれている。2GB 10MB 恐らく後者ではなかろうか？」とある。
- ホットワードは再利用向けとセッション単位向けに分かれ、背景コンテキストも利用できる。 [^]
  - Footnote: 機能表で事前コンパイル済みホットワード、インスタントホットワード、プロンプトコンテキストの説明とユースケースが示されている。
- 日本語を含む約 30 の主要言語に対応すると説明されている。 [^]
  - Footnote: 記事に「30ほどの主要言語に対応」「日本語含む」とある。
- 非リアルタイムの同期 HTTP API は URL または Base64 の音声入力で利用されている。 [^]
  - Footnote: 非リアルタイム節に「音声ファイルは、URL指定もしくはBase64エンコードでの指定」と記載されている。
- 5 分程度の日本語音声に対して 15〜20 秒程度で応答したと報告されている。 [^]
  - Footnote: curl 実行後の説明で「15〜20秒程度で応答が返ってくる」とある。

## 「Audio8/Audio8-TTS-Preview-0.6b」を試す

### Executive Summary
- Audio8-TTS Preview 0.6B は、601M パラメータの小型多言語 TTS モデルとして紹介されている。
- 対応言語は日本語を含む 11 言語で、ゼロショット音声クローニングと参照なし推論をサポートする。
- モデルには 44.1 kHz のニューラルオーディオコーデックが同梱され、追加のコーデックチェックポイントは不要とされている。
- 評価では Seed-TTS の英語 WER 1.506、中国語 CER 0.950 など、小型ながら競争力のある数値が示されている。
- ただし比較は評価手法が異なるため厳密なランキングではなく、Preview の対応範囲を超える主張ではないと注意されている。
- Colaboratory L4 で試用し、ロード時の VRAM 消費は約 1.4GB、生成後は約 3.8GB 程度まで増えたと報告されている。
- リファレンス音声なしの日本語生成はできるが、2 回目でも壁時計で約 11.2 秒かかり、速度面には課題が残ると見られている。
- 日本語と英語のクロスリンガル音声クローンも試され、生成は可能だがリファレンスと言語を合わせる方がよさそうだと評価されている。
- ASR モデルは CC-BY-NC-4.0 だった一方、この TTS モデルは Apache 2.0 で公開されている点が好意的に受け止められている。

### Key Findings
- Audio8-TTS Preview は 0.6B 規模で多言語 TTS とゼロショット音声クローンを提供する。 [^]
  - Footnote: モデル説明に「パラメータ数0.6Bの多言語対応テキスト音声合成モデルで、ゼロショット音声クローン機能」とある。
- 対応言語には日本語、英語、中国語、韓国語、欧州言語など 11 言語が含まれる。 [^]
  - Footnote: 対応言語として「広東語、中国語、オランダ語、英語、フランス語、ドイツ語、イタリア語、日本語、韓国語、ポーランド語、スペイン語」が列挙されている。
